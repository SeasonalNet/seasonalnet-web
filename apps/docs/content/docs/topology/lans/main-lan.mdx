## Public Web Routing via SeasonalWeb

SeasonalWeb receives public HTTP/HTTPS traffic and routes hostname-based services to the appropriate internal backend. Cloudflare remains the public DNS and TLS edge for proxied hostnames.

| Hostname | SeasonalWeb backend | Authentication / Exposure | Notes |
|---|---|---|---|
| `docs.seasonalnet.org` | SeasonalWeb / SeasonalNet docs app | Public via Cloudflare | Rendered public documentation site. `VMs/` content must remain excluded. |
| `grafana.seasonalnet.org` | `http://192.168.1.15:3000` | Public via Cloudflare; Grafana uses Authentik OAuth/OIDC with a local break-glass admin account retained | SeasonalMonitor dashboard front door. Prometheus (`192.168.1.15:9090`) is intentionally not published. |

## Known Remaining Items

- CME-rack Dell PowerEdge R230 and SeasonalR340 use Main-LAN addressing over VLAN 99 transit rather than sitting behind `10.42.2.0/24` on SeasonalEDGE-R1
- SeasonalBack currently stores PBS data on its VM root filesystem / single virtual disk. Re-document if a separate datastore disk, passthrough disk, direct-attached storage layout, or SeasonalNAS-backed backup storage layout is added.
- SeasonalMonitor SNMP polling and Redfish/iDRAC collection have a working foundation; continue expanding dashboards and target coverage as needed.
- SeasonalBRIDGE-NONROOT remains quarantined/disabled as a production path; clean up stale bridge IPv6/autoconfig details only if the Aironet bridge is revisited.
