## What SeasonalNet is

SeasonalNet is the overall solo-operated homelab and service platform run by seasonal.currency.

It includes infrastructure, communications systems, web front doors, operational tooling, development services, control-plane services, VPN access, and weather-related systems.

SeasonalNet is the platform as a whole. It is not limited to weather operations.

## What SeasonalNet is not

SeasonalNet is not only SeasonalWeather.
SeasonalNet is not only the network topology.
SeasonalNet is not only one VM host, one service, or one runtime.
SeasonalNet is not fully represented by any single subsystem.

## Operator model

SeasonalNet is operated by one primary operator: seasonal.currency.

It is a personal homelab and service platform, not a multi-team enterprise environment.

## Major platform domains

### Seasonal Agent

Seasonal Agent is the former local assistant runtime used for operator support, inspection, reasoning, and bounded read-only tool execution.

Seasonal Agent is a subsystem of SeasonalNet. It is not the whole platform.

### SeasonalWeather

SeasonalWeather is the weather, alerting, and radio-oriented subsystem (primary station name: "Jetstream / WXK435"). The current runtime VM is SeasonalWX at `192.168.1.10`.

SeasonalWeather is an important subsystem within SeasonalNet, but it does not define all of SeasonalNet.

### Voice and communications systems

These include SeasonalPBX and Cisco Unified Communications Manager Express.

- SeasonalPBX is the current FreePBX/Asterisk service VM at `192.168.1.12`. It handles traditional SIP and public community PBX traffic.
- For internal, older Cisco based telephony lab usage. SeasonalCME-R1 runs older Cisco 79xx series phones through CUCME/CME.
- `pbx-controld` is the PBX control-plane daemon for coordinating bot-managed and portal-managed extension states on SeasonalPBX.

### VPN and remote administration

`moon` is also the Defguard/WireGuard remote-access platform at `192.168.1.23`. Its routed VPN LANs are `10.88.0.0/24` and `fd97:418:22dd:88::/64`.

The VPN is an authenticated remote administration plane. Access to internal networks remains subject to Defguard/MFA and routing policy rather than treating the VPN as an unrestricted extension of Main LAN.

### Web and platform services

These include public front doors, authentication-related services, Git services, DNS, LAN private CA, mail, documentation, and supporting utilities.

### Control-plane services

Control-plane services coordinate state and operations between user-facing interfaces, automation, and downstream systems.

The current first dedicated control-plane daemon is `pbx-controld`, hosted on `moon` (`192.168.1.23`) and backed by PostgreSQL on `moon` (`192.168.1.23`). Its initial purpose is to prevent the PBX SPA, Discord bot, and FreePBX from maintaining conflicting extension lifecycle truth.

### Infrastructure and operations

These include VM hosts, network topology, observability checks, backup systems, storage systems, database services, Docker/container services, sandbox execution services, VPN services, and supporting operational tooling.

SeasonalR230 and SeasonalR340 are the active Proxmox hosts. SeasonalR230 hosts the consolidated `moon` service VM plus SeasonalPBX and SeasonalWX. SeasonalR340 hosts the `arctic` backup VM and the `meteor` VM.

The active R230 service fleet is `moon` (100), SeasonalPBX (106) and SeasonalWX (107). The active R340 support VM set is `arctic` (VMID 116) and `meteor` (103).

SeasonalMonitor is the current observability spine for infrastructure reachability, dashboards, SNMP, and Redfish collection. Grafana is exposed publicly at `grafana.seasonalnet.org` through `moon` with Authentik OAuth/OIDC; Prometheus remains a private backend service.

Slate (`192.168.1.40`) is the primary admin/development workstation and Teal (`192.168.1.41`) is the secondary admin/build workstation. Both run Fedora Linux 45 KDE Plasma Edition and provide normal Forgejo CI capacity. Cobalt (`192.168.1.42`) also runs Fedora 45 KDE, but currently serves only as the opt-in slow CI host. None of these systems is a production deployment host.

## Network addressing model

Main-LAN uses native ISP-assigned IPv6, and a `192.168.1.0/24` IPv4 RFC1918 LAN for addressing.

Routed private IPv6 segments use the SeasonalNet ULA allocation `fd97:418:22dd::/48`, subdivided into one `/64` per LAN or functional segment.

OSPF provides dynamic routing for IPv4/v6 subnets between DSW1, the FW4C, and CME-R1. The WNC-CR200A has return routes for internal VLANs through the FW4C.

## Grounding and truth rules for agents

Documentation describes intended design, stable terminology, and platform reference facts.

Runtime tools provide live operational truth.

If runtime tool output and docs disagree, runtime tool output is authoritative for current state.
