## What SeasonalNet is

SeasonalNet is the overall solo-operated homelab and service platform run by Seasonal_Currency.

It includes infrastructure, communications systems, web front doors, operational tooling, development services, control-plane services, and weather-related systems.

SeasonalNet is the platform as a whole. It is not limited to weather operations.

## What SeasonalNet is not

SeasonalNet is not only SeasonalWeather.
SeasonalNet is not only the network topology.
SeasonalNet is not only one VM host, one service, or one runtime.
SeasonalNet is not fully represented by any single subsystem.

## Operator model

SeasonalNet is operated by one primary operator: Seasonal_Currency.

It is a personal homelab and service platform, not a multi-team enterprise environment.

## Major platform domains

### Seasonal Agent

Seasonal Agent is the local assistant runtime used for operator support, inspection, reasoning, and bounded read-only tool execution.

Seasonal Agent is a subsystem of SeasonalNet. It is not the whole platform.

### SeasonalWeather

SeasonalWeather is the weather, alerting, and radio-oriented subsystem. The current runtime VM is SeasonalWX at `192.168.1.10`; the older VM named SeasonalWeather has been retired and replaced.

SeasonalWeather is an important subsystem within SeasonalNet, but it does not define all of SeasonalNet.

### Voice and communications systems

These include PBX, CME, phone provisioning, and related communications services.

SeasonalPBX is the current FreePBX/Asterisk VM at `192.168.1.12` and the Phone-LAN gateway at `192.168.56.1`. `pbx-controld` is the new PBX control-plane daemon for coordinating bot-managed and portal-managed extension state.

### Web and platform services

These include public front doors, authentication-related services, Git services, DNS, mail, documentation, and supporting utilities.

### Control-plane services

Control-plane services coordinate state and operations between user-facing interfaces, automation, and downstream systems.

The current first dedicated control-plane daemon is `pbx-controld`, hosted on SeasonalDock (`192.168.1.20`) and backed by PostgreSQL on SeasonalDB (`192.168.1.19`). Its initial purpose is to prevent the PBX SPA, Discord bot, and FreePBX from maintaining conflicting extension lifecycle truth.

### Infrastructure and operations

These include VM hosts, network topology, observability checks, backup systems, storage systems, database services, Docker/container services, sandbox execution services, and supporting operational tooling.

SeasonalR230 and SeasonalR340 are the active Proxmox hosts. SeasonalR230 is the primary VM host for the main service fleet. SeasonalR340 hosts backup, storage, sandbox, database, and Docker/control-plane support VMs.

The active R230 service fleet is SeasonalDNS (VMID 101), SeasonalAuth (102), SeasonalForge (103), SeasonalMail (104), SeasonalMonitor (105), SeasonalPBX (106), SeasonalWX (107), SeasonalRain (108), and SeasonalWeb / SeasonalNet (109). The active R340 support VM set is SeasonalBack (VMID 100), SeasonalNAS (VMID 110), SeasonalSand (VMID 111), SeasonalDB (VMID 112), and SeasonalDock (VMID 113). These VMs have QEMU Guest Agent enabled/responding where configured, Proxmox autostart configured, and verified PBS backups on SeasonalBack where applicable.

SeasonalMonitor is the current observability spine for infrastructure reachability, dashboards, SNMP, and Redfish collection. Grafana is exposed publicly at `grafana.seasonalnet.org` through SeasonalWeb with Authentik OAuth/OIDC; Prometheus remains a private backend service.

Admin workstations such as seasonal-victus (`192.168.1.40`) and seasonal-teal-laptop (`192.168.1.41`) are admin clients. They should not become long-lived application deployment hosts or accumulate project dependency trees when a service VM is more appropriate.

## Grounding and truth rules

Documentation describes intended design, stable terminology, and platform reference facts.

Runtime tools provide live operational truth.

If runtime tool output and docs disagree, runtime tool output is authoritative for current state.
