## Purpose

This document describes the major systems that make up SeasonalNet and the role each system serves.

This is platform reference material. It is not a live status page.

## Core systems

### Seasonal Agent

Role: local, former assistant runtime for operator-facing support, reasoning, and bounded read-only inspection.

Boundary: answers about live state should use tools when available.

### SeasonalWeather / SeasonalWX

Role: weather, alerting, broadcast, and related operational workflows.

The current SeasonalWeather runtime VM is **SeasonalWX** at `192.168.1.10`. It replaced the older VM named SeasonalWeather, which is now retired. Internal DNS aliases for the current VM include `wx.lan.seasonalnet.org`, `seasonalwx.lan.seasonalnet.org`, and `seasonalweather.lan.seasonalnet.org`. SeasonalWX exposes the SeasonalWeather API through an nginx LAN-side reverse proxy on HTTP port 80, with application routes under `/v1/...` rather than `/api/v1/...`.

Boundary: SeasonalWeather is one subsystem within SeasonalNet, not a synonym for the whole platform. VM naming should distinguish the current host `SeasonalWX` from the broader SeasonalWeather service/subsystem.

### SeasonalPBX, CME, and phone services

Role: telephony, call control, phone provisioning, and related communications functions. SeasonalPBX is the current FreePBX/Asterisk service VM at `192.168.1.12`; it is not a Phone-LAN router or gateway. SeasonalNet-DSW1 owns the routed gateway for Phone-LAN VLAN 30 and the Voice VLAN 10 / Management VLAN 42 gateways used by SeasonalCME. SeasonalCME-R1 remains the CME application node at `10.10.0.10` plus `fd97:418:22dd:10::10`, while FW4C provides the production upstream firewall/NAT boundary.

Boundary: voice systems are part of SeasonalNet's communications domain.

### SeasonalVPN

Role: authenticated remote-access VPN and routed administration plane.

SeasonalVPN is a Dockerized Defguard VPN stack running on `moon` under SeasonalR230. It uses `192.168.1.23` on Main LAN and runs Defguard/WireGuard services. The VPN overlay uses `10.88.0.0/24` for IPv4 and `fd97:418:22dd:88::/64` for IPv6 ULA addressing, with gateway addresses `10.88.0.1` and `fd97:418:22dd:88::1`.

Boundary: SeasonalVPN provides controlled remote access. It does not replace Main-LAN routing policy, and VPN clients remain subject to Defguard/MFA and routed access controls.

### PBX control plane / pbx-controld

Role: authoritative coordination layer for bot-managed and portal-managed PBX extension state.

`pbx-controld` runs on `moon` under Docker Compose. It is a Node.js / TypeScript Fastify service. It uses the `pbx_control` PostgreSQL database on `moon` (`192.168.1.23`) and the `pbx` schema for extension ownership, operations, audit logs, reconcile runs, and migration state.

Boundary: `pbx-controld` is intended to prevent the SPA, Discord bot, and FreePBX from each maintaining conflicting extension truth. UI clients and bot clients should use the control-plane API rather than mutating bot-managed extension state directly.

### Auth, Git, DNS, mail, and platform support services

Role: identity, code hosting, internal DNS, LAN private CA, mail, and supporting service infrastructure. `moon` provides Authentik, Forgejo (`git.seasonalnet.org`), the mailcow stack (`mail.seasonalnet.org`), and SeasonalCA from the shared Docker host at `192.168.1.23`.

Boundary: these services support operator workflows and platform administration.

### SeasonalDNS

Role: internal Main-LAN DNS resolver and local DNS management service running Technitium DNS Server.

SeasonalDNS runs on `moon` and retains `192.168.1.14` as its Main-LAN service address. It manages internal records under `lan.seasonalnet.org`. Cloudflare remains authoritative for public `seasonalnet.org` DNS. Admin/static hosts should prefer SeasonalDNS directly for internal DNS lookups to avoid stale router-side local-name answers.

Boundary: SeasonalDNS is not public authoritative DNS for `seasonalnet.org`; Cloudflare remains authoritative for public SeasonalNet DNS.

### SeasonalCA

Role: LAN private certificate authority for internal SeasonalNet TLS.

SeasonalCA runs at `192.168.1.23` on `moon` and provides the SeasonalCA / Smallstep step-ca service for LAN trust. Internal DNS names include `seasonalca.lan.seasonalnet.org` and `ca.lan.seasonalnet.org`. Legacy Cisco infrastructure uses a separate RSA chain/SCEP path exposed internally as `ca-rsa.lan.seasonalnet.org`, keeping legacy RSA enrollment separate from the primary CA path.

Boundary: SeasonalCA is an internal trust service for LAN/private TLS. It is not a public WebPKI CA and should not be documented as authoritative for public `seasonalnet.org` certificates.

### SeasonalMonitor

Role: first-pass observability spine for SeasonalNet infrastructure.

SeasonalMonitor runs as a containerized stack on `moon` and provides Prometheus, Grafana, blackbox_exporter, snmp_exporter, Redfish/iDRAC monitoring, and node_exporter coverage. Its network-device monitoring configuration follows the current NET-MGMT and DSW1/ASW1/SW3 topology.

Grafana is publicly reachable at `https://grafana.seasonalnet.org` through the `moon` web front door and uses Authentik OAuth/OIDC. A local Grafana admin account is retained as break-glass access. Prometheus remains private and should not be published directly.

Boundary: SeasonalMonitor is observability infrastructure. It does not replace SeasonalAgent and does not mutate infrastructure. The standard Prometheus/Grafana/SNMP/Redfish foundation should remain the base before adding custom monitoring behavior.

### SeasonalR230 primary VM host

Role: primary Proxmox host for the active SeasonalNet service VM fleet.

SeasonalR230 is the Dell PowerEdge R230 Proxmox host at `192.168.1.30`, with iDRAC at `10.41.0.32` on BMC-MGMT/VLAN 41. It is connected through the CME rack VLAN 99 Main-LAN transit path. Its current service VMs are `moon` (VMID 100), SeasonalPBX (106), and SeasonalWX (107).

Boundary: SeasonalR230 is the primary VM host, not the backup service. Backup service ownership remains with `arctic`.

### meteor

Role: shared storage / NAS service VM for SeasonalNet support workloads.

`meteor` is an OpenMediaVault VM hosted on SeasonalR340 as Proxmox VMID `103`. It uses `192.168.1.25` on Main LAN, with hostname/DNS `meteor.lan.seasonalnet.org`. It provides shared storage paths used by internal services.

Boundary: `meteor` is the storage service VM, not the R340 hypervisor itself.

### SeasonalR340 and arctic

Role: secondary Proxmox host and backup/storage platform for local SeasonalNet infrastructure.

SeasonalR340 is the Dell PowerEdge R340 Proxmox host at `192.168.1.31`, with iDRAC at `10.41.0.33` on BMC-MGMT/VLAN 41. It is connected through the CME rack VLAN 99 Main-LAN transit path and hosts `meteor` (VMID 103) and `arctic` (VMID 116).

`arctic` is the Proxmox Backup Server VM hosted on SeasonalR340 at `192.168.1.24`. It replaces the former SeasonalBack VM at `192.168.1.16`.

Boundary: `arctic` is the backup service VM, `meteor` is the storage service VM, and SeasonalR340 is the hypervisor. Do not document PBS or NAS services as running directly on the R340 host.

### Retired systems

The older VM named SeasonalWeather is retired and replaced by SeasonalWX at `192.168.1.10`. Keep `SeasonalWeather` as the subsystem/service name, but use `SeasonalWX` for the current VM host.

SeasonalUtilities is retired. It previously occupied `192.168.1.11` and hosted utility functions such as Uptime Kuma, but the VM has been archived and removed from the active VirtualBox inventory. Treat `192.168.1.11` as reserved until a replacement utility host is deliberately assigned. The former public status service is retired.

The former dedicated SeasonalAuth, SeasonalForge, SeasonalWeb, SeasonalRain, SeasonalMail, SeasonalMonitor, SeasonalBack, SeasonalSand, SeasonalDB, SeasonalDock, SeasonalCA, and SeasonalVPN VM assignments are retired. Their former Main-LAN addresses remain reserved unless explicitly reused; their active service roles were consolidated onto `moon`, replaced by `arctic`, or retired.

### Web front doors and SPAs

Role: browser-facing interfaces for platform functions such as docs, radio, PBX, provisioning, and agent access. The reverse proxy and SeasonalNet SPAs run on `moon`, including the public documentation site.

Boundary: a web front door may expose part of SeasonalNet, but not the full live platform state by itself.

## Operational notes

### Proxmox live networking restarts

During the 2026-06-07 LAN reshuffle, live networking restarts on SeasonalR230 and SeasonalR340 detached VM tap interfaces from `vmbr0`. Host management addresses stayed reachable, but guest VMs were isolated until their tap interfaces were reattached to `vmbr0`.

Avoid `systemctl restart networking` on Proxmox hosts while VMs are live unless prepared to repair bridge membership or reboot during maintenance.

## Observability boundaries

SeasonalMonitor is the central first-pass metrics and dashboarding system. Grafana is the human-facing dashboard front end; Prometheus is the private metrics backend; exporters collect host, reachability, SNMP, and Redfish state.

Seasonal Agent may inspect some parts of SeasonalNet through configured tools and caller context.

It should not assume that one instrumented runtime host exposes the entire platform.

Questions about current live state should use tools when available.
Questions about platform identity, subsystem boundaries, or intended design may be answered from docs.
