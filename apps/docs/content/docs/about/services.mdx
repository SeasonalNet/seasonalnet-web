## Purpose

This document describes the major systems that make up SeasonalNet and the role each system serves.

This is platform reference material. It is not a live status page.

## Core systems

### Seasonal Agent

Role: local assistant runtime for operator-facing support, reasoning, and bounded read-only inspection.

Boundary: answers about live state should use tools when available.

### SeasonalWeather / SeasonalWX

Role: weather, alerting, broadcast, and related operational workflows.

The current SeasonalWeather runtime VM is **SeasonalWX** at `192.168.1.10`. It replaced the older VM named SeasonalWeather, which is now retired. Internal DNS aliases for the current VM include `wx.lan.seasonalnet.org`, `seasonalwx.lan.seasonalnet.org`, and `seasonalweather.lan.seasonalnet.org`. SeasonalWX exposes the SeasonalWeather API through an nginx LAN-side reverse proxy on HTTP port 80, with application routes under `/v1/...` rather than `/api/v1/...`.

Boundary: SeasonalWeather is one subsystem within SeasonalNet, not a synonym for the whole platform. VM naming should distinguish the current host `SeasonalWX` from the broader SeasonalWeather service/subsystem.

### SeasonalPBX, CME, and phone services

Role: telephony, call control, phone provisioning, and related communications functions. SeasonalPBX is the current FreePBX/Asterisk service VM at `192.168.1.12`; it is no longer the Phone-LAN router or gateway. Phone-LAN has moved to `10.30.0.0/24` and `fd42:30::/64`, with routing ownership to be documented after the managed-switch/trunk cutover.

Boundary: voice systems are part of SeasonalNet's communications domain.

### PBX control plane / pbx-controld

Role: authoritative coordination layer for bot-managed and portal-managed PBX extension state.

`pbx-controld` runs on SeasonalDock at `/opt/pbx-controld` under Docker Compose. It is a Node.js / TypeScript Fastify service bound to `127.0.0.1:9091` inside SeasonalDock. It uses the `pbx_control` PostgreSQL database on SeasonalDB (`192.168.1.19`) and the `pbx` schema for extension ownership, operations, audit logs, reconcile runs, and migration state.

Boundary: `pbx-controld` is intended to prevent the SPA, Discord bot, and FreePBX from each maintaining conflicting extension truth. UI clients and bot clients should use the control-plane API rather than mutating bot-managed extension state directly.

### Auth, Git, DNS, mail, and platform support services

Role: identity, code hosting, internal DNS, LAN private CA, mail, and supporting service infrastructure. SeasonalAuth provides the Authentik identity layer at `192.168.1.6`; SeasonalForge provides Forgejo/git service at `192.168.1.7` / `git.seasonalnet.org`; SeasonalMail is the mailcow-backed mail server at `192.168.1.13` for `mail.seasonalnet.org`; SeasonalCA provides the LAN private CA at `192.168.1.21`.

Boundary: these services support operator workflows and platform administration.

### SeasonalDNS

Role: internal Main-LAN DNS resolver and local DNS management service running Technitium DNS Server.

SeasonalDNS runs at `192.168.1.14` on SeasonalR230. It manages internal records under `lan.seasonalnet.org`. Cloudflare remains authoritative for public `seasonalnet.org` DNS. Admin/static hosts should prefer SeasonalDNS directly for internal DNS lookups to avoid stale router-side local-name answers.

Boundary: SeasonalDNS is not public authoritative DNS for `seasonalnet.org`; Cloudflare remains authoritative for public SeasonalNet DNS.


### SeasonalCA

Role: LAN private certificate authority for internal SeasonalNet TLS.

SeasonalCA runs at `192.168.1.21` and provides the SeasonalCA / Smallstep step-ca service for LAN trust. Internal DNS names include `seasonalca.lan.seasonalnet.org` and `ca.lan.seasonalnet.org`.

Boundary: SeasonalCA is an internal trust service for LAN/private TLS. It is not a public WebPKI CA and should not be documented as authoritative for public `seasonalnet.org` certificates.

### SeasonalMonitor

Role: first-pass observability spine for SeasonalNet infrastructure.

SeasonalMonitor runs on `192.168.1.15` and provides Prometheus, Grafana, blackbox_exporter, snmp_exporter, Redfish/iDRAC monitoring, and host-native node_exporter. Its current targets include SeasonalMonitor itself, SeasonalDNS, SeasonalR230, R230 iDRAC, SeasonalR340 / R340 iDRAC, SeasonalCME-SW2, and CME rack backhaul reachability.

Grafana is publicly reachable at `https://grafana.seasonalnet.org` through SeasonalWeb and uses Authentik OAuth/OIDC. A local Grafana admin account is retained as break-glass access. Prometheus remains private and should not be published directly.

Boundary: SeasonalMonitor is observability infrastructure. It does not replace SeasonalAgent and does not mutate infrastructure. The standard Prometheus/Grafana/SNMP/Redfish foundation should remain the base before adding custom monitoring behavior.

### SeasonalR230 primary VM host

Role: primary Proxmox host for the active SeasonalNet service VM fleet.

SeasonalR230 is the Dell PowerEdge R230 Proxmox host at `192.168.1.30`, with iDRAC at `192.168.1.32`. It is connected through the CME rack VLAN 99 Main-LAN transit path. The current R230 service VM fleet is SeasonalDNS (VMID 101), SeasonalAuth (102), SeasonalForge (103), SeasonalMail (104), SeasonalMonitor (105), SeasonalPBX (106), SeasonalWX (107), SeasonalRain (108), and SeasonalWeb / SeasonalNet (109). These VMs have QEMU Guest Agent enabled/responding, Proxmox autostart configured, and verified PBS backups on SeasonalBack.

Boundary: SeasonalR230 is the primary VM host, not the backup service. Backup service ownership remains with SeasonalBack.

### SeasonalDB

Role: shared PostgreSQL database host for SeasonalNet control-plane data.

SeasonalDB is a Debian 13 VM hosted on SeasonalR340 as Proxmox VMID `112`. It uses `192.168.1.19` on Main LAN via interface `ens18`, with hostname/DNS `seasonaldb.lan.seasonalnet.org`. PostgreSQL 18 runs under Docker Compose from `/opt/seasonaldb`, with data under `/srv/seasonaldb/postgres` and backups under `/srv/seasonaldb/backups`. The current primary application database is `pbx_control`; its `pbx` schema includes extension ownership, operation, audit, reconcile, and migration tables for `pbx-controld`.

Boundary: SeasonalDB is a database host. It should not be treated as a general application host.

### SeasonalDock

Role: Docker/control-plane application host.

SeasonalDock is a Debian 13 VM hosted on SeasonalR340 as Proxmox VMID `113`. It uses `192.168.1.20` on Main LAN via interface `ens18`, with hostname/DNS `seasonaldock.lan.seasonalnet.org`. Docker Engine and Docker Compose are installed from Docker's official Debian repository. Its first hosted application is `pbx-controld` at `/opt/pbx-controld`.

Boundary: SeasonalDock hosts containerized application/control-plane services. It keeps Node.js/TypeScript runtime and dependency churn off admin workstations such as seasonal-victus.

### SeasonalNAS

Role: shared storage / NAS service VM for SeasonalNet support workloads.

SeasonalNAS is a Debian 13 VM hosted on SeasonalR340 as Proxmox VMID `110`. It uses `192.168.1.17` on Main LAN via interface `ens18`, with hostname/DNS `seasonalnas.lan.seasonalnet.org`. It provides shared storage paths used by other internal services; SeasonalSand mounts SeasonalNAS-backed workspace and artifact paths for sandbox job execution.

Boundary: SeasonalNAS is the storage service VM, not the R340 hypervisor itself. Do not treat Docker bridge addresses on SeasonalNAS as routed Main-LAN service addresses.

### SeasonalSand / SeasonalSandbox

Role: isolated sandbox execution service for bounded internal automation workloads.

SeasonalSand is a Debian 13 VM hosted on SeasonalR340 as Proxmox VMID `111`. It uses `192.168.1.18` on Main LAN via interface `ens18`, with hostname/DNS `seasonalsand.lan.seasonalnet.org`. It runs `seasonal-sandboxd` under Docker Compose. The sandbox API is bound host-local inside the VM on `127.0.0.1:9090`, and the service uses SeasonalNAS-backed workspace and artifact paths.

Boundary: SeasonalSand is a controlled execution/sandbox service. It should not be documented as a general-purpose shell host, public API, or replacement for Seasonal Agent.

### SeasonalR340 and SeasonalBack

Role: secondary Proxmox host and backup/storage/sandbox/database/Docker support platform for local SeasonalNet infrastructure.

SeasonalR340 is the Dell PowerEdge R340 Proxmox host at `192.168.1.31`, with iDRAC at `192.168.1.33`. It is connected through the CME rack VLAN 99 Main-LAN transit path and hosts SeasonalBack (VMID 100), SeasonalNAS (VMID 110), SeasonalSand (VMID 111), SeasonalDB (VMID 112), and SeasonalDock (VMID 113).

SeasonalBack is the Proxmox Backup Server VM hosted on SeasonalR340. It uses `192.168.1.16`; `seasonalback.lan.seasonalnet.org` resolves to that address, and `back.lan.seasonalnet.org` is a service alias. Its datastore is named `seasonalback` at `/mnt/datastore/seasonalback`. The current datastore backing is the PBS VM root filesystem / single virtual disk, not a separate mounted data disk.

Boundary: SeasonalBack is the backup service VM. SeasonalNAS is the storage service VM. SeasonalSand is the sandbox service VM. SeasonalDB is the database service VM. SeasonalDock is the container/control-plane application host. SeasonalR340 is the hypervisor and hardware platform. Do not document PBS, NAS, sandbox, database, or Docker application services as running directly on the R340 host unless that design changes.

### Retired systems

The older VM named SeasonalWeather is retired and replaced by SeasonalWX at `192.168.1.10`. Keep `SeasonalWeather` as the subsystem/service name, but use `SeasonalWX` for the current VM host.

SeasonalUtilities is retired. It previously occupied `192.168.1.11` and hosted utility functions such as Uptime Kuma, but the VM has been archived and removed from the active VirtualBox inventory. Treat `192.168.1.11` as reserved until a replacement utility host is deliberately assigned. The former public status service is retired.

### Web front doors and SPAs

Role: browser-facing interfaces for platform functions such as docs, radio, PBX, provisioning, and agent access. SeasonalWeb / SeasonalNet runs as VMID 109 on SeasonalR230 and serves the reverse-proxy and Next.js SPA front-door role, including the public documentation site.

Boundary: a web front door may expose part of SeasonalNet, but not the full live platform state by itself.

## Operational notes

### Proxmox live networking restarts

During the 2026-06-07 LAN reshuffle, live networking restarts on SeasonalR230 and SeasonalR340 detached VM tap interfaces from `vmbr0`. Host management addresses stayed reachable, but guest VMs were isolated until their tap interfaces were reattached to `vmbr0`.

Avoid `systemctl restart networking` on Proxmox hosts while VMs are live unless prepared to repair bridge membership or reboot during maintenance.

## Observability boundaries

SeasonalMonitor is the central first-pass metrics and dashboarding system. Grafana is the human-facing dashboard front end; Prometheus is the private metrics backend; exporters collect host, reachability, SNMP, and Redfish state.

Seasonal Agent may inspect some parts of SeasonalNet through configured tools and caller context.

It should not assume that one instrumented runtime host exposes the entire platform.

Questions about current live state should use tools when available.
Questions about platform identity, subsystem boundaries, or intended design may be answered from docs.
