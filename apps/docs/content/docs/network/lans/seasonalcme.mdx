**Voice subnet:** `10.42.0.0/24` (VLAN 10)  
**Management subnet:** `10.42.2.0/24` (VLAN 42)  
**Voice IPv6 ULA:** `FD42:42::/64`  
**Management IPv6 ULA:** `FD42:42:2::/64`  
**Voice gateway:** `10.42.0.1` / `FD42:42::1` (SeasonalEDGE-R1 `Gi0/1`)  
**Management gateway:** `10.42.2.1` / `FD42:42:2::1` (SeasonalEDGE-R1 `Vlan42`)  
**Last updated:** 2026-04-26

---

## Networks / VLANs

| VLAN / Network | Purpose | Gateway | Notes |
|---|---|---|---|
| `VLAN 10` / `10.42.0.0/24` | SeasonalCME voice / endpoint network | `10.42.0.1` | Main CME lab access VLAN; carries CME router, phones, AP, and voice clients |
| `VLAN 10` / `FD42:42::/64` | SeasonalCME voice IPv6 ULA | `FD42:42::1` | IPv6 ULA on the voice segment; RA/DHCPv6 served by SeasonalEDGE-R1 |
| `VLAN 42` / `10.42.2.0/24` | SeasonalCME management network | `10.42.2.1` | Routed from SeasonalEDGE-R1 via `Vlan42`; trunked between SW1 and SW2 |
| `VLAN 42` / `FD42:42:2::/64` | SeasonalCME management IPv6 ULA | `FD42:42:2::1` | IPv6 ULA for management on `Vlan42` |
| `VLAN 99` | WAN / transit infrastructure VLAN | none on switches | Used as native VLAN on the SW1↔SW2 trunk and for the edge transit path; also suitable for select Main-LAN-addressed rack-local endpoints such as the R230 with iDRAC 8 |

## Address Bands

### Voice VLAN 10 (`10.42.0.0/24`)

| Range | Purpose |
|---|---|
| `.1` | Gateway |
| `.2 – .9` | Network infrastructure |
| `.10 – .19` | Core voice infrastructure |
| `.20 – .49` | Reserved static voice devices / important endpoints |
| `.50 – .99` | Static or semi-static lab endpoints |
| `.100 – .254` | DHCP pool / dynamic clients |

Current fixed assignments on VLAN 10 already align with this banding: `10.42.0.1` (SeasonalEDGE-R1), `10.42.0.2` (SeasonalCME-SW1), `10.42.0.3` (SeasonalCME-SW2), `10.42.0.4` (SeasonalAP-3602i), and `10.42.0.10` (SeasonalCME-R1).

### Management VLAN 42 (`10.42.2.0/24`)

| Range | Purpose |
|---|---|
| `.1` | Gateway |
| `.2 – .19` | Static management infrastructure |
| `.20 – .49` | Reserved static managed devices |
| `.50 – .99` | Static management expansion / headroom |
| `.100 – .254` | Reserved for future DHCP if ever needed |

`10.42.2.0/24` is presently best treated as reserved static management space. VLAN 42 is already routed and trunked, but the documented switch management addresses are still on `Vlan10`; move management-plane addresses there only as a deliberate follow-up migration.

## Topology Summary

```text
Main LAN / Home LAN (192.168.1.0/24)
        |
        |  SeasonalEDGE-R1 Gi0/0 = 192.168.1.4
        |
SeasonalEDGE-R1
  |- Gi0/1 = 10.42.0.1 / FD42:42::1  --> SW1 Gi0/24 (VLAN 10 voice)
  `- Vlan42 = 10.42.2.1 / FD42:42:2::1

SW1 (root)
  |- Gi0/21 --> SeasonalCME-R1 Gi0/0 = 10.42.0.10
  |- Gi0/22 --> SeasonalEDGE-R1 Gi0/0 transit side (VLAN 99)
  `- Gi0/23 <== trunk 10,42,99 / native 99 ==> SW2 Gi1/0/24

SW2 (PoE)
  |- Gi1/0/1 --> SeasonalBridge-NONROOT (VLAN 99)
  |- Gi1/0/2 --> SeasonalAP-3602i (VLAN 10)
  |- planned access VLAN 99 port --> SeasonalR230 / iDRAC (Main-LAN addressed)
  `- Gi1/0/9+ --> phones / voice clients (VLAN 10)
```

## Known Remaining Items

- `SeasonalCME-SW1 Gi0/24` has a stale interface description. CDP shows it is connected to **SeasonalEDGE-R1 `Gi0/1`**, but the description still references **SeasonalCME-R1**.
- `SeasonalCME-SW1 Gi0/22` and `SeasonalEDGE-R1 Gi0/0` form the VLAN 99 transit-side relationship seen in CDP; this is distinct from the voice-side `Gi0/24` ↔ `Gi0/1` link.
- `VLAN 42` is present and trunked between SW1 and SW2, but no switch SVI for VLAN 42 was shown on the 2960-X switches in the captured output; management addresses shown on the switches are on `Vlan10`.
- `SeasonalBridge-NONROOT` remains part of the broader SeasonalNet bridge path back toward main LAN, but from the CME side it is attached on SW2 `Gi1/0/1` in VLAN 99.
