## Notes and Constraints

- Phone-LAN is a **flat LAN**, not a VLAN-backed fabric. Physical switching is presently unmanaged, so the map records the L3/L2 segment and observed devices rather than a port-by-port switch topology.
- FreePBX17 still has `enp0s3` on the VirtualBox NAT network (`10.0.2.15`), and nftables still contains an IPv4 masquerade rule for `enp0s3`, but the active default route for current Phone-LAN egress is `enp0s9`.
- The AP has both a Phone-LAN ULA (`FD42:56::4`)
- The capture showed Router Advertisements sourced from FreePBX17 on the Phone-LAN segment, confirming IPv6 LAN gateway behavior.
- The capture also showed SIP keepalive / OPTIONS / NOTIFY traffic between FreePBX17 and the observed phones, plus direct NTP from client devices to upstream servers.
